# Ustaz Student App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **Execution (Mohamed's decision):** implemented by Codex (`codex exec` in the repo) task by task; Claude reviews each diff and runs the checks; Claude takes over if Codex hits its limit.

**Goal:** Flutter student app (Android first, iOS supported) for the Ustaz tutoring platform.

**Architecture:** GetX modules (binding + controller + view) over repositories that wrap one `ApiClient`. One
`BaseController` owns loading/error/empty states, one `AssessmentPlayer` module serves quizzes, homework and exams.
Branding and strings come from config/translation files only.

**Tech Stack:** Flutter (latest stable), Dart 3, GetX, `md_player_android` (git), Firebase Messaging (optional).

**Spec:** `docs/superpowers/specs/2026-10-19-ustaz-design.md` · **API:** `docs/api-contract.md` (binding)

## Global Constraints

- Monorepo path: `app/`. Package name `ustaz`, application id `dev.muhdroid.ustaz` (renamed per client in one place).
- Runtime packages allowed: `get`, `get_storage`, `http`, `cached_network_image`,
  `md_player_android` (git `https://github.com/MUHZERO/md-player.git`, ref `1e049803cf0c3ec1c4a39bec3fbe9cffe94fede2`),
  `youtube_player_iframe` (iOS fallback only), `pdfrx` (PDF, MIT), `firebase_core` + `firebase_messaging`,
  `uuid`. Any other package needs a written reason in the commit body. No `dio`, no Syncfusion, no device-info.
- YouTube stream resolution happens inside md-player (it already depends on `youtube_explode_dart`, so the spec's
  `youtube_explode_dart` requirement is met without a direct dependency); the app never
  shows or logs the YouTube id or URL.
- Android: `FLAG_SECURE` on the whole app via `MainActivity` (no package). iOS: listen to
  `UIScreen.capturedDidChange` through a small method channel and pause video while captured.
- No hard-coded user-facing strings: `lib/core/i18n/{ar,en}.dart` GetX translations; default `ar`, RTL.
- No client branding: name, colors, logo from `lib/core/config/app_config.dart` + `assets/brand/`.
- No duplicated code: any widget or logic used twice moves to `lib/core/widgets` or a shared service.
- Firebase optional: if `firebase_options.dart` is absent the app runs with push disabled (no crash).
- `flutter analyze` clean, `dart format` clean, widget/unit tests for every controller. Run the touched test file
  while iterating; full `flutter test` before each commit. Commits small, no attribution lines.

## Review Focus

1. Network drops in the middle of an exam → answers already chosen are kept locally and re-sent; the timer keeps
   counting from server `deadline_at`, not from the phone clock (Task 8 test `timer uses server deadline`,
   `pending answers are retried`).
2. App killed and reopened during an exam → resumes the same attempt with its answers (Task 8 test `resume restores answers`).
3. Token revoked by the teacher (password reset/device approved elsewhere) → any 401 sends the student to login once,
   without a loop of dialogs (Task 1 test `401 logs out once`).
4. Locked segment tapped (gating quiz not passed) → explains why and jumps to the quiz, never opens the video (Task 5
   test `tapping locked segment opens the gating quiz`).
5. Video stream fails to resolve (YouTube change, region) → error state with retry; on iOS the iframe fallback is used
   (Task 6 test `player falls back on resolve error`).

### Task 6: Video player, watermark, progress

**Files:** `modules/player/*`, `core/security/{screen_capture_guard,watermark}.dart`, `services/progress_reporter.dart`, `data/repositories/progress_repository.dart`, `ios/Runner/AppDelegate.swift` (capture channel), tests

**Interfaces:**
- `abstract class VideoSource { Future<void> init(String youtubeId, Duration startAt); Stream<Duration> get position; void pause(); Widget view(); Future<void> dispose(); }` with `MdPlayerSource` (Android, `MdPlayerController.network('https://www.youtube.com/watch?v=$id')`) and `IframeSource` (iOS, `youtube_player_iframe`, controls without YouTube branding links). `VideoSource.forPlatform()` picks one; Android falls back to `IframeSource` when resolve throws.
- `Watermark` overlays student name + phone, opacity 0.25, moves to a random corner every 20 s.
- `ProgressReporter(segmentId)` posts `{segment_id, position_seconds, watched_seconds}` every 15 s and on pause/dispose; failures are dropped (next tick resends larger values).
- `ScreenCaptureGuard.isCaptured` stream (iOS channel `ustaz/screen_capture`; Android always false — FLAG_SECURE covers it); player pauses while captured.

- [ ] **Step 1: Failing tests (fakes for VideoSource):** `resumes at last position`; `reports progress every 15 seconds`; `pauses while screen is captured`; `player falls back on resolve error`; `watermark shows student name and phone`; `youtube id never appears in widget tree text`.
- [ ] **Step 2:** Implement. **Step 3:** Run → PASS; manual check on an Android emulator with a demo lecture. Commit `feat: protected video player with progress`.
